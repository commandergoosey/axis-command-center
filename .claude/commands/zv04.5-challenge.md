# Scope & Premise Challenge (Optional)

Run this after `/zv04-plan` and before `/zv05-execute` when you want to stress-test the plan before committing to it.

## Step 0: Read the Plan

Read the most recent plan in `ai/zv/plans/`. Identify the GitHub issue, scope, and key decisions.

## Step 1: Premise Challenge

1. **Is this the right problem?** Could a different framing yield a dramatically simpler solution?
2. **What is the actual user/business outcome?** Is the plan the most direct path, or is it solving a proxy problem?
3. **What happens if we do nothing?** Real pain point or hypothetical?

## Step 2: Existing Code Leverage

1. What existing code already partially solves each sub-problem? Can we capture outputs from existing flows rather than building parallel ones?
2. Is this plan rebuilding anything that already exists? If yes, why rebuild vs refactor?

## Step 3: Complexity Check

- If the plan touches **8+ files** or introduces **2+ new abstractions**, treat that as a smell.
- Challenge whether the same goal can be achieved with fewer moving parts.
- Propose a minimal alternative if one exists.

## Step 4: Dream State Mapping

```
CURRENT STATE              THIS PLAN                  6-MONTH IDEAL
[describe]       --->      [describe delta]    --->    [describe target]
```

Does this plan move toward or away from the ideal? Does it create tech debt that blocks future work?

## Step 5: GitHub Issue Cross-Reference

Check related GitHub issues:
- Does this plan block or unlock deferred work?
- Can any deferred items be bundled without expanding scope?
- Does this plan create new work that should be captured as issues?

## Output

Present findings as individual questions. For each concern:
- State the problem in plain English
- Present 2-3 options including "proceed as planned"
- Give your recommendation with reasoning

If no issues found: "Plan looks solid. Proceed to `/zv05-execute`."

If scope changes are accepted, update the plan file in `ai/zv/plans/` with the revisions.

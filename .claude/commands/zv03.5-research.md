# Deep Internet Research (Optional)

This step is **optional**. Skip straight to `/zv04-plan` if the task is purely codebase-internal (bug fix, refactor, internal wiring) with no external parallels worth researching.

Use this step when the task benefits from outside knowledge: competitive analysis, library selection, UX patterns, architecture approaches, or gotchas others have hit.

> **Need deeper research?** Use `/research-pipeline` instead — it adds Firecrawl page extraction on top of Perplexity discovery for full-content synthesis rather than summary-of-summary.

## Input

Either:
- A completed `/zv03-explore` exploration (reference the exploration doc in `ai/zv/explorations/`)
- A standalone research topic described by the user

## Your Responsibilities

**Do NOT implement anything.** Research only.

### 1. Define Research Questions

Based on the exploration or topic, list 3-6 specific research questions. Examples:
- "What libraries exist for X? Tradeoffs?"
- "How do [Product A, Product B] handle this UX pattern?"
- "What are common pitfalls when implementing X?"
- "What's the current best practice for X in Next.js / React / Supabase?"

Confirm the questions with the user before proceeding.

### 2. Research Execution

Use the available research tools in this priority order:

1. **Perplexity MCP** (primary):
   - **Default**: Use `perplexity_ask` for most questions — it's fast, cheap, and sufficient for 90% of research needs.
   - **Follow-up**: Use `perplexity_search` for finding specific URLs, repos, or recent news.
   - **EXPENSIVE — use sparingly**: `perplexity_research` (sonar-deep-research) costs ~$2-3 per call. Only use when the user explicitly asks for "deep research" or the question genuinely requires multi-source investigative synthesis (e.g., comprehensive competitive analysis, novel architectural decisions with no clear consensus).
   - **Never** run `perplexity_research` in parallel — it has rate limits and each call is expensive.
2. **Brave Search MCP** (`brave_web_search`) — Use for quick factual lookups, finding specific GitHub repos, or as fallback if Perplexity is unavailable.
3. **WebSearch / WebFetch** — Use to pull specific pages, docs, or README content identified by the above tools.

Run `perplexity_ask` / `perplexity_search` queries in parallel when they are independent. Never run `perplexity_research` in parallel.

**Cost logging (#343):** After every Perplexity MCP call, if the response includes a `usage` field, record the spend in the shared log so it's visible alongside `scripts/intel-scrape.mjs` spend. Run via Bash:

```bash
node /Users/commandergoosey/Projects/axis/scripts/perplexity-log-spend.mjs \
  --source zv03.5-research \
  --model <model> \
  --usage '<usage-json>' \
  [--topic <short-label>]
```

- `<model>` = `sonar`, `sonar-pro`, `sonar-reasoning`, `sonar-reasoning-pro`, or `sonar-deep-research`
- `<usage-json>` = the full `usage` object the MCP response returned (pass through verbatim — the CLI parses `prompt_tokens`, `completion_tokens`, `citation_tokens`, `reasoning_tokens`, `num_search_queries` if present)
- The CLI prints the dollar cost to stdout and appends one line to `.overnight/perplexity-cost.jsonl`

If the MCP response does not expose `usage` (possible with older MCP versions), skip the logging step and note it in the research doc's "Credits Used" section.

### 3. Synthesize Findings

For each research question, summarize:
- **Answer** — the key finding in 2-4 sentences
- **Sources** — links to the most useful references
- **Relevance** — how this applies to our specific task (high / medium / low)

### 4. Recommendations

Based on all findings, provide:
- **Libraries to consider** — with pros/cons and install size / maintenance status
- **Patterns to adopt** — specific approaches worth following
- **Pitfalls to avoid** — things others got wrong that we should sidestep
- **Open questions** — anything that still needs human judgment
